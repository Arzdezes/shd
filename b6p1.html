Лабораторная работа: iSCSI Target и Initiator

Тема: Настройка iSCSI Target на ALT Server с использованием пакета scsitarget-utils (tgt), подключение Initiator с ALT Workstation с помощью open-iscsi, работа с блочными устройствами, настройка аутентификации CHAP.

Цель работы: Научиться настраивать iSCSI Target с использованием пакета scsitarget-utils (демон tgt), подключаться к нему с помощью open-iscsi, создавать файловые системы на удалённых блочных устройствах, а также настраивать CHAP-аутентификацию.

Топология:

  • Сервер (Target): ALT Server 11 (виртуальная машина)
  • Клиент (Initiator): ALT Workstation 10.4 (хостовая система)

Подготовка

Важно: Для выполнения команд с правами администратора мы будем использовать su -.
Переключитесь в режим root на обеих машинах.

1.1 Проверка сетевого взаимодействия

На сервере (ALT Server):

su -
ip a

Запомните IP-адрес сервера (в примере используется 192.168.122.206).

На клиенте (ALT Workstation):

su -
ping -c 3 192.168.122.206

1.2 Установка необходимых пакетов

Особенность ALT Linux: Для iSCSI Target используется пакет scsitarget-utils, который предоставляет демон tgt и утилиты tgtadm, tgt-admin. Для клиента используется open-iscsi.

На сервере:

apt-get update
apt-get install scsitarget-utils
Пояснение: Пакет scsitarget-utils содержит демон tgt, который реализует iSCSI Target, а также утилиты tgtadm (для ручного управления) и tgt-admin (для работы с конфигурационными файлами). В ALT Linux это стандартное решение для организации iSCSI Target.

На клиенте:

apt-get update
apt-get install open-iscsi multipath-tools
Пояснение: Пакет open-iscsi содержит демон iscsid и утилиту iscsiadm для работы с iSCSI-целями. multipath-tools понадобится во второй лабораторной работе.

1.3 Создание виртуального диска на сервере

Пояснение: Для демонстрации iSCSI удобно использовать файлы-образы вместо физических дисков. Это безопасно и не требует дополнительного оборудования.

На сервере:

Создаём каталог для образов дисков

mkdir -p /srv/iscsi

Создаём файл-образ размером 1 ГБ

dd if=/dev/zero of=/srv/iscsi/disk1.img bs=1M count=1024

Проверяем

ls -lh /srv/iscsi/
Вопрос: Почему для iSCSI удобно использовать файлы-образы, а не целые диски? Какие преимущества и недостатки у этого подхода?

Этап 2: Настройка iSCSI Target через конфигурационный файл

2.1 Структура конфигурационного файла

Основной конфигурационный файл tgt — /etc/tgt/targets.conf. Он имеет HTML-подобную структуру с тегами <target> и </target>.

Просмотр файла конфигурации по умолчанию

cat /etc/tgt/targets.conf

2.2 Редактирование конфигурации

Откроем файл для редактирования:

nano /etc/tgt/targets.conf

Добавим в конец файла следующую конфигурацию:

<target iqn.2025-04.com.example:server.disk1>
    # Базовое устройство хранения (файл)
    backing-store /srv/iscsi/disk1.img
    
    # Опции для повышения производительности
    write-cache on
    
    # Контроль доступа (разрешаем все IP в локальной сети)
    initiator-address 192.168.0.0/16<
</target>
Пояснение: backing-store указывает путь к блочному устройству или файлу-образу. write-cache on включает кэширование записи для повышения производительности. initiator-address ограничивает доступ к цели только указанной подсетью.

2.3 Запуск и проверка сервиса

Запускаем сервис tgt

systemctl enable tgt
systemctl start tgt

Проверяем статус

systemctl status tgt

2.4 Проверка экспортированных целей

Просмотр всех целей (targets)

tgt-admin --show

Или с помощью tgtadm

tgtadm --lld iscsi --mode target --op show

Пример вывода:

Target 1: iqn.2025-04.com.example:server.disk1
    System information:
        Driver: iscsi
        State: ready
    I_T nexus information:
    LUN information:
        LUN: 0
            Type: controller
            SCSI ID: IET     00010000
            SCSI SN: beaf10
            Size: 0 MB
            Backing store: No
        LUN: 1
            Type: disk
            SCSI ID: IET     00010001
            SCSI SN: beaf11
            Size: 1074 MB
            Backing store: /srv/iscsi/disk1.img
    Account information:
    ACL information:
        192.168.0.0/16

Вопрос: Что означает LUN 0 в выводе? Почему он присутствует всегда?

Пояснение: LUN 0 — это всегда контроллер (виртуальное устройство управления). Фактические диски начинаются с LUN 1. Это стандартное поведение протокола SCSI.

Этап 3: Настройка iSCSI Initiator

3.1 Проверка демона iscsid

На клиенте (ALT Workstation):

systemctl status iscsid

Если сервис не активен, запустите:

systemctl enable iscsid
systemctl start iscsid
Пояснение: Демон iscsid управляет соединениями iSCSI и обрабатывает задачи аутентификации.

3.2 Обнаружение целей (Discovery)

Обнаруживаем доступные iSCSI цели на сервере

iscsiadm -m discovery -t sendtargets -p 192.168.122.206
Пояснение: Команда отправляет запрос на порт 3260 сервера и возвращает список доступных целей. Результат сохраняется в базе данных /var/lib/iscsi/send_targets/.

3.3 Подключение к цели (Login)

Подключаемся ко всем обнаруженным целям

iscsiadm -m node --login

Также можно подключиться к конкретной цели:

iscsiadm -m node -T iqn.2025-04.com.example:server.disk1 -p 192.168.122.206 --login

3.4 Проверка подключения

Просмотр активных сессий

iscsiadm -m session

Более детальная информация

iscsiadm -m session -P 1

Просмотр новых блочных устройств

lsblk

Вопрос: Какое новое устройство появилось в системе? Какого оно размера?

Пояснение: После подключения iSCSI LUN отображается как обычный блочный диск (например, /dev/sda). С ним можно работать как с любым другим диском.

Этап 4: Работа с iSCSI-устройством

4.1 Создание файловой системы

На клиенте:

Создаём файловую систему ext4 на iSCSI-диске (уточните имя устройства!)

mkfs.ext4 /dev/sda

Создаём точку монтирования

mkdir -p /mnt/iscsi_data

Монтируем

mount /dev/sda /mnt/iscsi_data

Проверяем

df -h /mnt/iscsi_data

4.2 Тестирование записи и чтения

Создаём тестовые файлы

echo "iSCSI test data with scsitarget-utils" > /mnt/iscsi_data/test.txt
dd if=/dev/urandom of=/mnt/iscsi_data/bigfile.dat bs=1M count=50

Проверяем

ls -la /mnt/iscsi_data/
du -sh /mnt/iscsi_data/

4.3 Настройка автоматического монтирования

Для автоматического монтирования при загрузке нужно добавить запись в /etc/fstab.

Важно: использовать опцию _netdev, указывающую, что устройство зависит от сети.

Пример:

/dev/sda /mnt/iscsi_data ext4 defaults,_netdev 0 0

Этап 5: Настройка CHAP-аутентификации

5.1 Почему нужна аутентификация

Вопрос: В чём опасность отключения аутентификации в iSCSI?

Пояснение: Без аутентификации любой, кто имеет доступ к сети, может подключиться к iSCSI Target и получить доступ к данным. CHAP (Challenge-Handshake Authentication Protocol) решает эту проблему, требуя пароль при подключении.

5.2 Настройка CHAP на сервере

На сервере отредактируем /etc/tgt/targets.conf, добавив параметры аутентификации:

nano /etc/tgt/targets.conf

Приведём конфигурацию к следующему виду:

<target iqn.2025-04.com.example:server.disk1>
    # Базовое устройство хранения
    backing-store /srv/iscsi/disk1.img
    
    # Опции производительности
    write-cache on
    
    # Контроль доступа по IP
    initiator-address 192.168.122.0/24
    
    # CHAP-аутентификация (incominguser = username password)
    incominguser iscsi_user secret123
</target>
Пояснение: Директива incominguser задаёт имя пользователя и пароль, которые клиент должен предоставить при подключении.

5.3 Перезагрузка конфигурации Target

Перезагружаем конфигурацию tgt

systemctl restart tgt

Проверяем, что цель с CHAP отображается правильно

tgt-admin --show

5.4 Настройка CHAP на клиенте

На клиенте:

Отключаемся от цели (если подключены):

iscsiadm -m node --logout

Настраиваем CHAP в файле конфигурации:

nano /etc/iscsi/iscsid.conf

Найдите и раскомментируйте (или добавьте) следующие строки:

node.session.auth.authmethod = CHAP
node.session.auth.username = iscsi_user
node.session.auth.password = secret123

Для обнаружения также может потребоваться аутентификация

discovery.sendtargets.auth.authmethod = CHAP
discovery.sendtargets.auth.username = iscsi_user
discovery.sendtargets.auth.password = secret123

Обнаруживаем цели заново

iscsiadm -m discovery -t sendtargets -p 192.168.122.206

Подключаемся:

iscsiadm -m node --login

Проверяем:

iscsiadm -m session
lsblk
Вопрос: Что произойдёт, если указать неправильный пароль в конфигурации?

Этап 6: Очистка

На клиенте:

Размонтируем

umount /mnt/iscsi_data

Удаляем запись из fstab (если добавляли)

Отключаемся от iSCSI

iscsiadm -m node --logout

Опционально: удаляем цель из базы

iscsiadm -m node -T iqn.2025-04.com.example:server.disk1 -p 192.168.122.206 -o delete

На сервере:

Останавливаем сервис

systemctl stop tgt

Удаляем образ диска (опционально)

rm -f /srv/iscsi/disk1.img

Выводы

  • iSCSI позволяет предоставлять блочные устройства по IP-сети.
  • В ALT Linux для настройки iSCSI Target используется пакет scsitarget-utils (демон tgt).
  • Конфигурация Target задаётся в файле /etc/tgt/targets.conf.
  • Для подключения к iSCSI Target на клиенте используется пакет open-iscsi.
  • После подключения iSCSI LUN отображается как обычное блочное устройство (/dev/sdb).
  • Для безопасности в production-среде необходимо использовать CHAP-аутентификацию (incominguser).
