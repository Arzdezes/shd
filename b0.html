Вводная лекция: Системы хранения данных — от теории к практике

Цель лекции: Сформировать общее представление о системах хранения данных (СХД), их месте в IT-инфраструктуре, ключевых технологиях и задачах, которые решает администратор хранилищ. Лекция даёт "карту местности" для всех последующих тем курса.

Введение

Что такое системы хранения данных и зачем им нужен отдельный курс?

Вопрос к аудитории: Как вы думаете, сколько данных создаётся в мире каждую минуту?

Ответ: более 1,7 мегабайт на человека в секунду, эксабайты в день)

Мы живём в эпоху данных. Каждую минуту:

  • Пользователи загружают тысячи часов видео на YouTube
  • Терабайты информации записываются в базы данных банков
  • Миллиарды датчиков IoT передают показания

Но дело не только в объёме. Проблема в том, что данные должны быть:

  • Доступны — когда они нужны
  • Целостны — не повреждены
  • Безопасны — защищены от несанкционированного доступа
  • Сохраняемы — не потеряны при отказах оборудования
  • Производительны — обрабатываться с приемлемой скоростью

Системы хранения данных — это целая область IT, которая решает эти задачи. В этом курсе мы пройдём путь от одного диска до петабайтных распределённых хранилищ.

  1. Понимать архитектуры хранения: DAS, NAS, SAN, SDS, HCI.
  2. Настраивать классические технологии: LVM, RAID, iSCSI, NFS, Samba.
  3. Работать с современными файловыми системами: ZFS, BTRFS.
  4. Применять объектные хранилища: S3, MinIO.
  5. Строить гиперконвергентные инфраструктуры: Ceph, Proxmox VE.

Часть 1. Классификация систем хранения

1.1 По месту подключения

DAS (Direct Attached Storage) — непосредственно подключённое хранилище

┌─────────────┐
│   Сервер    │
│      │      │
│   ┌──┴────┐ │
│   │  HDD  │ │
│   └───────┘ │
└─────────────┘
  • Диски подключены напрямую к серверу (SATA, SAS, NVMe).
  • Плюсы: Максимальная производительность, простота, низкая цена.
  • Минусы: Не разделяется между серверами, ограниченное масштабирование.
  • Примеры: Диск в вашем ноутбуке, диск в сервере.

NAS (Network Attached Storage) — сетевое файловое хранилище

┌─────────────┐     ┌─────────────┐
│   Сервер 1  │     │   Сервер 2  │
│      │      │     │      │      │
│      └──────┼─────┼──────┘      │
│             │     │             │
│      ┌──────┴─────┴──────┐      │
│      │   NAS (NFS/SMB)   │      │
│      └───────────────────┘      │
└─────────────┘     └─────────────┘
  • Данные передаются на уровне файлов (NFS, SMB).
  • Плюсы: Разделяется между серверами, простое управление.
  • Минусы: Оверхед на файловые операции, средняя производительность.
  • Примеры: Synology, QNAP, TrueNAS.

SAN (Storage Area Network) — сеть хранения данных

┌──────────────┐    ┌──────────────┐
│   Сервер 1   │    │   Сервер 2   │
│       │      │    │      │       │
│   ┌───┴─────┐│    │   ┌──┴──────┐│
│   │ FC/iSCSI││    │   │ FC/iSCSI││
│   └─┬───────┘│    │   └─┬───────┘│
│     │        │    │     │        │
└─────┼────────┘    └─────┼────────┘
      │                   │
   ┌──┴───────────────────┴───┐
   │   Дисковый массив (SAN)  │
   │   ┌─────┬─────┬─────┐    │
   │   │Диск1│Диск2│Диск3│    │
   │   └─────┴─────┴─────┘    │
   └──────────────────────────┘
  • Данные передаются на уровне блоков (iSCSI, Fibre Channel).
  • Плюсы: Высокая производительность, отказоустойчивость, масштабируемость.
  • Минусы: Высокая стоимость, сложность управления.
  • Примеры: Dell EMC PowerStore, NetApp AFF.

1.2 По уровню абстракции

Тип Единица хранения Протоколы Примеры
Блочное Блок (сектор) iSCSI, FC, NVMe-oF SAN, RBD (Ceph)
Файловое Файл (с иерархией) NFS, SMB NAS, CephFS

1.3 Архитектуры развёртывания

Традиционная трёхуровневая (3-tier)

  • Вычисления (серверы) → Сеть → Хранение (SAN/NAS)
  • Плюс: компоненты можно выбирать независимо
  • Минус: сложность управления, неэффективность ресурсов

Гиперконвергентная (HCI)

  • Вычисления и хранение в одних узлах
  • Плюс: простота, линейное масштабирование
  • Минус: конкуренция за ресурсы

Программно-определяемое хранилище (SDS)

  • ПО управляет разнородным железом
  • Плюс: гибкость, автоматизация
  • Минус: требуется обучение

Часть 2. Что происходит "под капотом"

2.1 От физического диска к файлу

Физический диск (NVMe, SATA, SAS)
       │
       ▼
Таблица разделов (MBR / GPT)   ← разбиваем диск на логические части
       │
       ▼
Файловая система (ext4, XFS)   ← организуем хранение файлов
       │
       ▼
Каталоги и файлы               ← то, что видит пользователь

Каждый слой добавляет свои возможности, но и свои ограничения.

2.2 Что такое файловая система?

Файловая система — это способ организации данных на диске. Она решает:

  • Где и как хранить содержимое файлов
  • Как быстро найти файл по имени
  • Как отслеживать свободное место
  • Как защитить данные при сбоях

Классические (журналируемые): ext4, XFS

  • Хорошо изучены, стабильны, высокопроизводительны
  • Но нет встроенных снапшотов, сжатия, контрольных сумм

Современные (CoW): ZFS, BTRFS

  • Copy-on-Write — никогда не перезаписывают существующие данные
  • Снапшоты, сжатие, контрольные суммы, самоисцеление
  • Требуют больше ресурсов, сложнее в настройке

2.3 Что такое RAID?

RAID (Redundant Array of Independent Disks) — объединение нескольких дисков в массив для повышения производительности и/или надёжности.

Уровень Как работает Полезная ёмкость Отказоустойчивость
RAID 0 Чередование (striping) Сумма всех дисков Нет
RAID 1 Зеркалирование (mirroring) 1 диск 1 диск
RAID 5 Чётность (parity) N-1 дисков 1 диск
RAID 6 Двойная чётность N-2 дисков 2 диска
RAID 10 Зеркало + чередование N/2 дисков до половины (но не в одной паре)

2.4 Что такое LVM?

LVM (Logical Volume Manager) — это прослойка между дисками и файловыми системами, которая позволяет:

  • Объединять несколько дисков в один пул (Volume Group)
  • Создавать гибкие логические тома (Logical Volumes)
  • Расширять и уменьшать тома без остановки системы
  • Создавать снапшоты для бэкапа

2.5 Что такое шифрование (LUKS)?

LUKS (Linux Unified Key Setup) — стандарт шифрования дисков в Linux:

  • Данные шифруются мастер-ключом
  • Мастер-ключ шифруется паролями пользователей
  • Есть 8 слотов для разных паролей
  • Смена пароля не требует перешифровки данных

Часть 3. Хранение по сети

3.1 Файловые протоколы

NFS (Network File System)

  • Родом из мира Unix
  • Простой, быстрый, stateless (v3)
  • Аутентификация по IP-адресу (небезопасно)

SMB/CIFS (Samba)

  • Стандарт в мире Windows
  • Stateful, богатые возможности блокировок
  • Аутентификация по паролю

3.2 Блочные протоколы

iSCSI (Internet SCSI)

  • Передаёт SCSI-команды по TCP/IP
  • Клиент видит удалённый диск как локальный
  • Отлично подходит для виртуализации

Fibre Channel (FC)

  • Специализированная высокоскоростная сеть
  • Очень низкая задержка, высокая стоимость
  • Применяется в корпоративных SAN

3.3 Объектные протоколы

S3 (Simple Storage Service)

  • REST API через HTTP/HTTPS
  • Плоское пространство имён (бакет → объект)
  • Масштабируется до эксабайт
  • Стал стандартом для облачных и on-premise хранилищ

Часть 4. Современные тенденции

4.1 Программно-определяемое хранение (SDS)

Что это: Управление хранилищем выносится из аппаратного контроллера в программный слой.

Примеры: Ceph, vSAN, Storage Spaces Direct

Преимущества:

  • Снижение стоимости (стандартные серверы)
  • Гибкость (политики вместо ручного управления)
  • Масштабирование (добавление узлов вместо замены дисков)

4.2 Гиперконвергентная инфраструктура (HCI)

Что это: Вычисления, хранение и сеть в одних узлах, управляемые через единую плоскость.

Примеры: VMware vSAN, Nutanix, Proxmox VE + Ceph

Преимущества:

  • Простота развёртывания
  • Линейное масштабирование
  • Ниже порог входа

4.3 Контейнеризация хранения

Kubernetes меняет подход к хранению:

  • CSI (Container Storage Interface) — стандарт для подключения систем хранения к K8s
  • Rook — оператор для Ceph в Kubernetes
  • Longhorn, OpenEBS — распределённое хранилище для контейнеров

4.4 Тренды на ближайшие годы

Тренд Описание
NVMe-oF NVMe over Fabrics — замена iSCSI и FC
Compute Express Link (CXL) Объединение памяти и устройств
Storage Class Memory (SCM) Новый класс памяти между RAM и SSD
AI для управления хранилищем Автоматическая оптимизация размещения данных

    • Блочный (iSCSI, FC)
