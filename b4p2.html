Лабораторная работа: Знакомство с BTRFS

Тема: Создание BTRFS-томов, работа с подтомами (subvolumes), снапшотами, управление RAID-профилями и понимание особенностей управления пространством.

Цель работы: На практике освоить основные команды BTRFS, понять разницу между подтомами и снапшотами, научиться изменять RAID-профили на лету, а также разобраться, почему df и btrfs filesystem usage показывают разные цифры.

Подготовка

Переключение в режим администратора

su -
Пояснение: Дальнейшие команды выполняются от имени root. Будьте внимательны — вы работаете с привилегированным доступом.

Установка BTRFS

apt-get update
apt-get install btrfs-progs
Пояснение: BTRFS — это файловая система, встроенная в ядро Linux. Утилиты для работы с ней поставляются в пакете btrfs-progs

Загрузка модуля ядра

modprobe btrfs
Пояснение: Модуль ядра загружается автоматически при монтировании BTRFS, но для уверенности можно выполнить вручную.

Создание loop-устройств для имитации дисков

Очищаем предыдущие назначения

losetup -D

Создаём 5 файлов-образов по 500 МБ каждый и назначаем их loop-устройствам

cd ~
mkdir btrfs_lab
cd btrfs_lab
for i in {1..5}; do dd if=/dev/zero of=disk$i.img bs=1M count=500; losetup /dev/loop$i ./disk$i.img; done

Проверяем, что получилось

lsblk | grep loop
Пояснение: Мы создали 5 виртуальных дисков по 500 МБ каждый. Явное назначение номеров гарантирует, что у всех студентов устройства называются одинаково.

Этап 1: Создание BTRFS-тома на одном диске

1.1 Форматирование и монтирование

Создаём BTRFS на одном диске

mkfs.btrfs -L mybtrfs /dev/loop1

Создаём точку монтирования и монтируем

mkdir /mnt/btrfs
mount /dev/loop1 /mnt/btrfs

Вопрос: Что вы видите в выводе mkfs.btrfs? Какие профили по умолчанию используются для данных и метаданных?

Пояснение: При создании BTRFS на одном диске данные обычно получают профиль single (одна копия), а метаданные — dup (две копии в разных местах диска). Это важно для надёжности.

1.2 Изучение структуры

Посмотрим информацию о файловой системе

btrfs filesystem show
btrfs filesystem df /mnt/btrfs
df -h /mnt/btrfs

Вопрос: Обратите внимание на разницу между df и btrfs filesystem df. Почему цифры отличаются?

Пояснение: df показывает свободное место в соответствии со стандартным механизмом ядра, а btrfs filesystem df — внутреннюю статистику BTRFS. Разница возникает из-за резервирования места под метаданные и механизма CoW.

Этап 2: Подтома (Subvolumes)

2.1 Создание подтомов

Подтома — это изолированные файловые системы внутри одного BTRFS-тома. Они похожи на разделы, но используют общее пространство.

Создаём подтома

btrfs subvolume create /mnt/btrfs/@home
btrfs subvolume create /mnt/btrfs/@data
btrfs subvolume create /mnt/btrfs/@backup

Смотрим список подтомов

btrfs subvolume list /mnt/btrfs

Вопрос: Что показывает команда btrf subvolume list? Обратите внимание на ID подтомов.

Пояснение:Каждый подтом имеет уникальный ID. Подтома не являются директориями в обычном смысле — они монтируются отдельно. Сейчас они видны как папки, потому что мы создали их внутри смонтированного корня.

2.2 Правильное монтирование подтомов

Создаём точки монтирования для подтомов

mkdir /mnt/home /mnt/data /mnt/backup

Монтируем подтома с использованием subvolid

umount /mnt/btrfs
mount -t btrfs -o subvolid=256 /dev/loop1 /mnt/home
mount -t btrfs -o subvolid=257 /dev/loop1 /mnt/data
mount -t btrfs -o subvolid=258 /dev/loop1 /mnt/backup

Вопрос: Что произойдёт, если смонтировать корневой том снова? С какими опциями нужно монтировать подтома при загрузке?

Пояснение: Подтома монтируются отдельно, как независимые файловые системы. Корневой подтом (ID 5) содержит в себе иерархию папок, но при монтировании подтомов напрямую их содержимое становится видно в точке монтирования.

Этап 3: Снапшоты

3.1 Создание данных и снапшота

Создаём тестовые файлы в подтоме @home

echo "Важные данные" > /mnt/home/important.txt
echo "Секреты" > /mnt/home/secret.txt

Создаём read-only снапшот

btrfs subvolume snapshot -r /mnt/home /mnt/home_snap

Смотрим список

btrfs subvolume list /mnt/btrfs

Вопрос: Какой ID у созданного снапшота? Почему команда snapshot выполнилась так быстро?

Пояснение: Снапшот в BTRFS — это мгновенная операция. Он не копирует данные, а создаёт новую точку в дереве файловой системы, ссылающуюся на те же блоки данных. Место начинает заниматься только при изменении оригинальных данных (CoW).

3.2 Изменение данных и наблюдение

Модифицируем файл в оригинале

echo "Дополнительная строка" >> /mnt/home/important.txt

Удаляем файл

rm /mnt/home/secret.txt

Создаём новый файл

echo "Новый файл" > /mnt/home/newfile.txt

Вопрос: Как вы думаете, изменилось ли содержимое снапшота?

Проверяем содержимое снапшота

cat /mnt/home_snap/important.txt
ls /mnt/home_snap/

Пояснение: Снапшот сохранил исходное состояние: файл important.txt без дополнительной строки, файл secret.txt существует, файла newfile.txt нет. Это демонстрирует механизм Copy-on-Write — старые блоки данных сохраняются для снапшота.

3.3 Монтирование снапшота для восстановления

Создаём точку монтирования для снапшота

mkdir /mnt/restore

Монтируем снапшот

mount -t btrfs -o subvolid=ID_СНАПШОТА /dev/loop1 /mnt/restore

Копируем данные обратно

cp -r /mnt/restore/* /mnt/home/

Проверяем

ls /mnt/home/

Вопрос: Какой командой можно смонтировать снапшот, зная его путь, а не ID?

Пояснение:Снапшоты — отличный инструмент для быстрого восстановления. В современных дистрибутивах снапшоты используются для отката системы после обновлений.

Этап 4: Управление RAID-профилями

4.1 Добавление дисков

Добавляем второй диск

btrfs device add /dev/loop2 /mnt/home

Проверяем

btrfs filesystem show
btrfs device usage /mnt/home

Вопрос: Изменился ли доступный объём после добавления диска? Почему?

Пояснение: Добавление диска само по себе не увеличивает полезное пространство — данные всё ещё используют профиль single. Нужно перебалансировать файловую систему.

4.2 Преобразование в RAID1

Преобразуем данные и метаданные в RAID1

btrfs balance start -dconvert=raid1 -mconvert=raid1 /mnt/home

Следим за процессом в другом терминале (опционально)

watch -n 1 btrfs balance status /mnt/home

Вопрос: Как изменился вывод btrfs filesystem df после балансировки? Сколько полезного места теперь доступно?

Пояснение: RAID1 в BTRFS означает "две копии данных на разных устройствах". Полезный объём при двух дисках равен объёму меньшего диска.

Проверяем результат

btrfs filesystem df /mnt/home
btrfs filesystem usage /mnt/home

Вопрос: Что показывает Device unallocated и как это связано со свободным местом?

Пояснение:Device unallocated — это блоки, которые ещё не назначены ни для данных, ни для метаданных. Они могут быть использованы при дальнейшей балансировке. Free (estimated) — это оценка реально доступного места для пользовательских данных.

4.3 Добавление третьего диска и переход на RAID10

Добавляем третий диск

btrfs device add /dev/loop3 /mnt/home

Попытка перейти на RAID10

btrfs balance start -dconvert=raid10 -mconvert=raid10 /mnt/home

Вопрос:Что произошло? Почему команда не выполнилась?

Пояснение: Для RAID10 нужно минимум 4 диска. BTRFS проверяет это перед началом балансировки и выдаёт ошибку.

Добавляем четвёртый диск

btrfs device add /dev/loop4 /mnt/home

Теперь RAID10 работает

btrfs balance start -dconvert=raid10 -mconvert=raid10 /mnt/home
btrfs filesystem usage /mnt/home

Вопрос: Как изменилась эффективность использования места при переходе с RAID1 на RAID10?

Этап 5: Иллюзия свободного места — почему df врёт

5.1 Создание ситуации с незаметным заполнением

Создаём много снапшотов

btrfs subvolume snapshot -r /mnt/home /mnt/home_snap1
dd if=/dev/urandom of=/mnt/home/bigfile1.dat bs=1M count=100

btrfs subvolume snapshot -r /mnt/home /mnt/home_snap2
dd if=/dev/urandom of=/mnt/home/bigfile2.dat bs=1M count=100

btrfs subvolume snapshot -r /mnt/home /mnt/home_snap3
dd if=/dev/urandom of=/mnt/home/bigfile3.dat bs=1M count=100

5.2 Сравнение выводов

Смотрим, что показывает df

df -h /mnt/home

Смотрим реальную картину

btrfs filesystem usage /mnt/home

Вопрос: Почему df показывает, что свободно 150 МБ, а btrfs filesystem usage говорит, что занято почти всё место?

Пояснение: df показывает только текущее состояние файловой системы, не учитывая снапшоты, которые хранят старые версии данных. Снапшоты могут занимать значительное место, и это место не видно в df. Вот почему для BTRFS важно использовать btrfs filesystem usage.

5.3 Удаление снапшотов и освобождение места

Удаляем снапшоты по одному

btrfs subvolume delete /mnt/home_snap1
btrfs subvolume delete /mnt/home_snap2
btrfs subvolume delete /mnt/home_snap3

Проверяем освобождение

btrfs filesystem usage /mnt/home

Пояснение: После удаления всех снапшотов, ссылающихся на старые блоки данных, место освобождается. Но может потребоваться балансировка, чтобы BTRFS перераспределила освободившееся пространство.

Этап 6: Scrub и проверка целостности

Запускаем проверку целостности данных

btrfs scrub start /mnt/home

Смотрим статус

btrfs scrub status /mnt/home

Вопрос: Что делает scrub? В чём его отличие от fsck?

Пояснение:scrub проверяет все данные и метаданные на диске на предмет ошибок. В отличие от fsck, он работает на смонтированной файловой системе и исправляет ошибки, используя избыточность (в RAID-конфигурациях).

Этап 7: Очистка

Размонтируем всё

umount /mnt/restore
umount /mnt/home
umount /mnt/data
umount /mnt/backup
umount /mnt/home_snap

Отключаем loop-устройства

losetup -D

Удаляем файлы-образы

cd ~
rm -rf btrfs_lab

  8. Почему RAID1 в BTRFS с двумя дисками даёт полезный объём, равный объёму одного диска?

Выводы

  • BTRFS объединяет управление томами, подтомами и снапшотами в одной файловой системе.
  • Подтома — это изолированные файловые системы внутри одного BTRFS-тома.
  • Снапшоты в BTRFS мгновенны и сначала не занимают места, но могут "съесть" всё пространство незаметно для df.
  • BTRFS позволяет изменять RAID-профили на лету с помощью btrfs balance.
  • Для мониторинга свободного места нужно использовать btrfs filesystem usage, а не df.
  • scrub — инструмент для проверки и восстановления целостности данных.
