Лабораторная работа №1: Введение в S3 на MinIO

Тема: Знакомство с объектнымхранилищем S3 на примере MinIO: установка на сервер, подключение с клиента, работачерез веб-консоль, CLI и API.

Цель работы: Освоить базовыепринципы работы объектного хранилища S3, научиться устанавливать и настраиватьMinIO в клиент-серверной архитектуре, выполнять основные операции с бакетамии объектами через веб-интерфейс, командную строку и программный API.

Топология:

  • Сервер: ALT Server 11 (виртуальнаямашина) — 192.168.56.101

  • Клиент: ALT Workstation 10.4 (хостовая система) — 192.168.56.1 (или другой адрес в сети 192.168.56.0/24)

Важное примечание о версии MinIO: В мае 2025 года MinIO изменила политику распространения: в community-версии (после RELEASE.2025-05-24) из веб-интерфейса удалены административные функции (управление пользователями, ключами доступа, политиками), оставлен только Object Browser для базовой работы с бакетами и файлами. Для полноценной демонстрации всех возможностей в лабораторной работе используется стабильная версия RELEASE.2025-04-22T22-12-26Z — последняя версия с полной веб-консолью.

Подготовка

Важно: Для выполнения команд с правами администратора мы будем использовать su -.
Переключитесь в режим root на обеих машинах.

1.1 Проверка сетевого взаимодействия

На сервере (ALT Server):

su -
ip a | grep 192.168.56

Запомните IP-адрес сервера (должен быть192.168.56.102 или аналогичный, который выдал DHCP).

На клиенте (ALT Workstation):

su -
ping -c 3 192.168.56.102

Пояснение: Убеждаемся, что клиент и сервер видят друг друга в сети. Это критически важно для клиент-серверной архитектуры.

1.2 Установка Docker на сервере

На сервере (ALT Server):

Установка Docker

apt-get update
apt-get install docker-io

Запуск Docker

systemctl enable docker
systemctl start docker

Проверка установки

docker --version

Пояснение: Docker позволяет легко запускать MinIO в изолированном контейнере без необходимости установки дополнительных зависимостей. Это стандартный способ развёртывания MinIO в production-среде.

1.3 Запуск MinIO Container (нужная версия)

На сервере (ALT Server):

Создаём директорию для данных MinIO

mkdir -p /data/minio

Запускаем контейнер MinIO версии с полной веб-консолью

docker run -d \
  --name minio-server \
  -p 9000:9000 \
  -p 9001:9001 \
  -v /data/minio:/data \
  -e "MINIO_ROOT_USER=minioadmin" \
  -e "MINIO_ROOT_PASSWORD=minioadmin123" \
  quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z \
  server /data --console-address ":9001"

Пояснение:

  • -d — запуск в фоновом режиме (detach)
  • --name minio-server — имя контейнера для удобного управления
  • -p 9000:9000 и -p 9001:9001 — проброс портов из контейнера на хост (API и веб-консоль)
  • -v /data/minio:/data — монтирование директории с данными на хост (чтобы данные сохранялись при перезапуске)
  • -e — установка переменных окружения (логин и пароль администратора)
  • Используется образ quay.io/minio/minio:RELEASE.2025-04-22T22-12-26Z — последняя версия с полным функционалом веб-консоли

1.4 Проверка работы контейнера

Просмотр запущенных контейнеров

docker ps

Просмотр логов (если что-то пошло не так)

docker logs minio-server

Пояснение: Контейнер должен быть в статусе Up. Если статус Exited — смотрите логи для диагностики.

1.5 Установка MinIO Client на хосте

Важное замечание о конфликте имён: Утилита MinIO Client называется mc, что совпадает с названием файлового менеджера Midnight Commander, который может быть установлен на хосте. В лабораторной работе мы будем использовать переименованную версию mcli, чтобы избежать конфликта.

На клиенте (ALT Workstation):

Скачиваем MinIO Client

wget https://dl.min.io/client/mc/release/linux-amd64/mc
chmod +x mc

Переименовываем (чтобы не конфликтовать с Midnight Commander)

mv mc /usr/local/bin/mcli

Проверяем установку

mcli --version

Пояснение: Конфликт имён между MinIO Client (mc) и Midnight Commander (mc) — известная проблема в мире Linux. Переименование в mcli — самое простое и безопасное решение.

Этап 2: Знакомство с веб-консолью MinIO

2.1 Подключение к веб-консоли

На клиенте (ALT Workstation):

  1. Откройте браузер на хосте.
  2. Перейдите по адресу: http://192.168.56.102:9001
  3. Введите учётные данные:
    • Username: minioadmin
    • Password: minioadmin123

Пояснение: Порт 9001 — это порт веб-консоли MinIO, которая предоставляет графический интерфейс для управления хранилищем.

2.2 Обзор интерфейса веб-консоли

После входа вы увидите главную панель управления (Dashboard). В используемой версии MinIO доступны следующие разделы:

Раздел Назначение Что можно делать
Dashboard Главная панель Просмотр общей информации о сервере: количество дисков, использованное пространство, uptime
Buckets Управление бакетами Создание, удаление, настройка бакетов (версионирование, квоты)
Object Browser Просмотр объектов Навигация по бакетам, просмотр и управление файлами
Access Keys Ключи доступа Создание и управление ключами доступа для приложений (важно для API-доступа)
Policies Политики доступа Создание и назначение политик доступа в формате JSON
Users Пользователи Управление пользователями и их правами
Groups Группы Управление группами пользователей
Settings Настройки Общие настройки MinIO сервера
Вопрос: Какие возможности веб-консоли вы считаете наиболее полезными для администратора хранилища?

2.3 Создание первого бакета через веб-консоль

  1. Перейдите в раздел Buckets (левое меню).
  2. Нажмите кнопку Create Bucket.
  3. Введите имя бакета: my-first-bucket (по правилам: только строчные буквы, цифры, дефисы).
  4. При создании можно настроить:
    • Versioning — версионирование объектов (рекомендуется включить для демонстрации)
    • Quota — ограничение размера бакета
  5. Нажмите Create Bucket.

Пояснение: Бакет — это контейнер для объектов. Имя бакета должно быть уникальным в пределах одной инсталляции MinIO.

2.4 Загрузка объектов через веб-консоль

  1. Войдите в бакет: Нажмите на имя my-first-bucket.
  2. Загрузите объект: Нажмите кнопку Upload, выберите любой файл на хосте (например, скриншот или текстовый документ).
  3. Добавьте текстовый объект: Используйте кнопку Upload → Create New File или просто создайте через CLI позже.
  4. Просмотр загруженных объектов: Теперь в бакете отображаются загруженные файлы.

Вопрос: Как в веб-консоли выглядит иерархия? Есть ли настоящие папки или это просто визуальное представление?

Пояснение: В объектных хранилищах нет настоящих папок. Символ / в имени объекта — это просто разделитель, который веб-интерфейс интерпретирует как папку для удобства пользователя. Это называется "плоское пространство имён" (flat namespace).

2.5 Управление объектами через веб-консоль

Выберите любой загруженный объект и изучите доступные действия:

Действие Описание
Share Создание временной публичной ссылки (presigned URL) для скачивания файла
Download Скачивание объекта на компьютер
>Delete Удаление объекта
Inspect Просмотр метаданных объекта
Preview Предварительный просмотр (для изображений, текстовых файлов)
Manage Tags Добавление тегов к объекту (ключ-значение)

2.6 Создание Access Key (для API-доступа)

Важно: Access Key и Secret Key нужны для подключения к MinIO через API (например, из Python-скриптов boto3). Без них программный доступ будет невозможен.
  1. Перейдите в раздел Access Keys (левое меню).
  2. Нажмите Create Access Key.
  3. При желании можно задать имя и политику доступа.
  4. Скопируйте сгенерированные Access Key и Secret Key (они понадобятся на этапе 4).

Пояснение: Access Keys — это учётные данные для API-доступа к S3-хранилищу. Они работают по аналогии с ключами в AWS IAM. Сами ключи можно увидеть только один раз — при создании.

2.7 Создание presigned URL (публичной ссылки)

  1. Выберите любой объект в бакете.
  2. Нажмите кнопку Share (или иконку с символом ссылки).
  3. Установите время действия ссылки (например, 10 минут).
  4. Нажмите Generate.
  5. Скопируйте полученную ссылку и попробуйте открыть её в другом браузере или режиме инкогнито.

Вопрос: Кто может скачать файл по этой ссылке? Почему это безопасно?

Пояснение: Presigned URL — это подписанный запрос на доступ к объекту. Он содержит временный токен, который MinIO проверяет перед выдачей файла. Даже если бакет приватный, по такой ссылке файл можно скачать в течение указанного времени. Это основной способ безопасного публичного доступа к объектам.

Этап 3: Работа через командную строку (mcli)

3.1 Настройка алиаса для подключения к серверу

На клиенте (ALT Workstation):

Настройка подключения к MinIO серверу

mcli alias set myminio http://192.168.56.102:9000 minioadmin minioadmin123

Проверка подключения

mcli admin info myminio

Пояснение: Команда alias set создаёт "алиас" (псевдоним) для подключения к серверу. Теперь все команды mcli с этим алиасом будут отправляться на наш MinIO сервер.

3.2 Базовые операции с бакетами

Создание бакета

mcli mb myminio/my-bucket-cli

Просмотр списка бакетов

mcli ls myminio/

Удаление бакета (только пустого)

mcli rb myminio/my-bucket-cli

3.3 Загрузка и скачивание объектов

Создание тестового файла

echo "Hello from CLI" > test.txt
dd if=/dev/urandom of=largefile.dat bs=1M count=50

Загрузка файла в бакет (аналог PUT)

mcli cp test.txt myminio/my-first-bucket/

Загрузка с другим именем (ключом)

mcli cp largefile.dat myminio/my-first-bucket/uploaded/largefile.dat

Просмотр объектов в бакете

mcli ls myminio/my-first-bucket/

Скачивание объекта

mcli cp myminio/my-first-bucket/test.txt downloaded.txt

Рекурсивное скачивание всех объектов

mcli cp --recursive myminio/my-first-bucket/ ./downloaded_all/
Вопрос: Обратите внимание на команду с uploaded/largefile.dat. Создалась ли настоящая папка uploaded? Как это проверить?

3.4 Управление правами доступа к бакету

Просмотр текущих прав

mcli anonymous get myminio/my-first-bucket

Установка публичного доступа (чтение для всех)

mcli anonymous set public myminio/my-first-bucket

Установка прав только на скачивание (без списка файлов)

mcli anonymous set download myminio/my-first-bucket

Возврат к приватному доступу

mcli anonymous set private myminio/my-first-bucket

Пояснение: В MinIO управление правами доступа к бакетам осуществляется через команду mcli anonymous. Это аналог политик доступа в AWS S3.

3.5 Управление Access Keys через CLI

Создание нового Access Key для пользователя

mcli admin user svcacct add myminio minioadmin --access-key myaccesskey --secret-key mysecretkey

Список Access Keys

mcli admin user svcacct list myminio minioadmin

Удаление Access Key

mcli admin user svcacct rm myminio minioadmin myaccesskey

3.6 Синхронизация папок (как rsync)

Создаём тестовую папку

mkdir -p test_sync/{folder1,folder2}
echo "file1 content" > test_sync/file1.txt
echo "file2 content" > test_sync/folder1/file2.txt

Синхронизация папки с бакетом

mcli sync ./test_sync/ myminio/my-first-bucket/sync_folder/

Просмотр результата

mcli tree myminio/my-first-bucket/

Пояснение: Команда mcli sync работает аналогично rsync — она копирует только изменённые файлы, что эффективно для больших объёмов данных.

Этап 4: Программный доступ через Python (boto3)

4.1 Установка boto3 на клиенте

На клиенте (ALT Workstation):

Установка pip и boto3

apt-get install python3-module-pip
pip3 install boto3

4.2 Настройка Access Key в переменные окружения

boto3 автоматически использует переменные окружения AWS_ACCESS_KEY_ID и AWS_SECRET_ACCESS_KEY:

export AWS_ACCESS_KEY_ID=<ваш_access_key>
export AWS_SECRET_ACCESS_KEY=<ваш_secret_key>

Пояснение: Access Key и Secret Key были созданы на этапе 2.6. Если вы их не сохранили — создайте новые через веб-консоль или CLI.

4.3 Написание и выполнение Python-скрипта

Создайте файл s3_demo.py:

#!/usr/bin/env python3
import boto3
from botocore.client import Config

# Конфигурация подключения к MinIO серверу
MINIO_ENDPOINT = "192.168.56.102:9000"
ACCESS_KEY = "minioadmin"  # или ваш созданный access key
SECRET_KEY = "minioadmin123"  # или ваш secret key
BUCKET_NAME = "my-first-bucket"

# 1. Создаём клиент для S3 (указываем endpoint нашего MinIO)
s3 = boto3.client(
    's3',
    endpoint_url=f'http://{MINIO_ENDPOINT}',
    aws_access_key_id=ACCESS_KEY,
    aws_secret_access_key=SECRET_KEY,
    config=Config(signature_version='s3v4'),
    region_name='us-east-1'
)

# 2. Просмотр списка бакетов
print("=== Список бакетов ===")
buckets = s3.list_buckets()
for bucket in buckets['Buckets']:
    print(f"  {bucket['Name']}")

# 3. Загрузка объекта (PUT)
print("\n=== Загрузка объекта ===")
with open('test.txt', 'rb') as f:
    s3.put_object(
        Bucket=BUCKET_NAME,
        Key='python/uploaded/from_python.txt',
        Body=f.read(),
        Metadata={'author': 'student', 'lab': 's3'}
    )
print("  Файл загружен в my-first-bucket/python/uploaded/from_python.txt")

# 4. Скачивание объекта (GET)
print("\n=== Скачивание объекта ===")
response = s3.get_object(Bucket=BUCKET_NAME, Key='test.txt')
content = response['Body'].read().decode('utf-8')
print(f"  Содержимое test.txt: {content}")

# 5. Генерация presigned URL (на 1 час)
print("\n=== Генерация presigned URL ===")
presigned_url = s3.generate_presigned_url(
    'get_object',
    Params={'Bucket': BUCKET_NAME, 'Key': 'test.txt'},
    ExpiresIn=3600
)
print(f"  Ссылка действительна 1 час: {presigned_url}")

# 6. Получение метаданных объекта (HEAD)
print("\n=== Метаданные объекта ===")
metadata = s3.head_object(Bucket=BUCKET_NAME, Key='python/uploaded/from_python.txt')
print(f"  Content-Type: {metadata.get('ContentType', 'unknown')}")
print(f"  Size: {metadata['ContentLength']} bytes")
print(f"  Metadata: {metadata.get('Metadata', {})}")

print("\nГотово!")

Запустите скрипт:

python3 s3_demo.py

Вопрос: Что такое presigned_url в коде? Где в реальном приложении это может пригодиться?

Пояснение: Boto3 — это официальный AWS SDK для Python. Он поддерживает подключение к любому S3-совместимому хранилищу через параметр endpoint_url. Это позволяет писать код, который будет работать как с Amazon S3, так и с on-premise MinIO.

Этап 5: Дополнительные эксперименты

5.1 Копирование между бакетами на сервере (Server-Side Copy)

Копирование объекта на сервере без скачивания на клиент

mcli cp myminio/my-first-bucket/test.txt myminio/my-first-bucket/copy/test_copy.txt

Вопрос: Чем отличается эта операция от cp на клиенте?

Пояснение: Server-Side Copy выполняется полностью на стороне сервера. Клиент не скачивает и не загружает данные, а только отправляет команду копирования. Это эффективно для больших файлов.

5.2 Просмотр информации о сервере через CLI

Статус сервера

mcli admin info myminio

Просмотр текущих операций

mcli admin top myminio

5.3 Управление контейнером Docker

Просмотр логов контейнера

docker logs minio-server

Перезапуск контейнера

docker restart minio-server

Остановка контейнера

docker stop minio-server

Запуск остановленного контейнера

docker start minio-server

Этап 6: Очистка

На сервере:

Останавливаем и удаляем контейнер

docker stop minio-server
docker rm minio-server

Опционально: очищаем данные

rm -rf /data/minio

На клиенте:

Удаляем тестовые файлы

rm -f test.txt largefile.dat downloaded.txt s3_demo.py

Удаляем временные папки

rm -rf downloaded_all/ test_sync/

  • MinIO предоставляет S3-совместимое объектное хранилище, которое можно развернуть на собственном сервере.
  • В мае 2025 года MinIO изменила политику распространения: в community-версии из веб-консоли удалены административные функции. Для полноценной работы используется версия RELEASE.2025-04-22T22-12-26Z.
  • В лабораторной работе использована реальная клиент-серверная архитектура: сервер в виртуальной машине, клиент на хосте.
  • При установке MinIO Client нужно учитывать возможный конфликт имён с Midnight Commander (mc → mcli).
  • Веб-консоль MinIO (порт 9001) предоставляет удобный графический интерфейс для управления бакетами, ключами доступа и пользователями.
  • Presigned URL — ключевой механизм безопасного публичного доступа к объектам в приватных бакетах.
  • Boto3 — стандартный SDK для работы с S3 из Python, который легко переключается между облачным S3 и on-premise MinIO через параметр endpoint_url.
