Лабораторная работа: Знакомство с ZFS.

Тема: Создание пулов ZFS, работа с dataset'ами, снапшотами и понимание особенностей CoW-архитектуры.

Цель работы: На практике освоить основные команды ZFS, понять разницу между пулом и dataset, научиться создавать снапшоты и откатываться к ним, а также разобраться, почему df может вводить в заблуждение.

Подготовка

Переключение в режим администратора

su -
Дальнейшие команды выполняются от имени root. Будьте внимательны — вы работаете с привилегированным доступом.

Установка ZFS

apt-get update
apt-get install zfs-utils kernel-module-zfs
ZFS состоит из двух частей — пользовательских утилит (zfs, zpool) и модуля ядра. Обе необходимо установить.

Загрузка модуля ядра

modprobe zfs
Модуль ядра можно загрузить командой modprobe. Убедиться, что он загружен, можно командой lsmod | grep zfs.

Создание loop-устройств для имитации дисков

Очищаем предыдущие назначения

losetup -D

Создаём 5 файлов-образов по 500 МБ каждый и назначаем их loop-устройствам

cd ~
mkdir zfs_lab
cd zfs_lab
for i in {1..5}; do dd if=/dev/zero of=disk$i.img bs=1M count=500; losetup /dev/loop$i ./disk$i.img; done

Проверяем, что получилось

lsblk | grep loop
Мы создали 5 виртуальных дисков по 500 МБ каждый. Они будут отображаться в системе как /dev/loop1 ... /dev/loop5.

Этап 1: Создание пула ZFS

1.1 Создание простого пула из одного диска

zpool create mypool /dev/loop1

Посмотрим, что появилось

zpool list
zfs list
df -h
ls -la /mypool
Команда zpool create сделала несколько вещей:
  1. Создала пул с именем mypool.
  2. Автоматически создала dataset с тем же именем.
  3. Смонтировала этот dataset в /mypool.

1.2 Создание зеркала (mirror).

Удалим предыдущий пул и создадим зеркало из двух дисков.

Удаляем пул

zpool destroy mypool

Проверяем, что пул исчез

zpool list

Создаём зеркало из loop1 и loop2

zpool create mirpool mirror /dev/loop1 /dev/loop2
Вопрос: Какой полезный объём у пула mirpool, если каждый диск по 500 МБ?

Проверяем

zpool list mirpool
df -h /mirpool
В зеркале из двух дисков полезный объём равен объёму одного диска (около 480 МБ с учётом служебной информации). Второй диск — точная копия первого.

1.3 Создание RAID-Z (аналог RAID5)

zpool destroy mirpool
zpool create rzpool raidz /dev/loop1 /dev/loop2 /dev/loop3
zpool list rzpool

Вопрос: Сколько полезного места в RAID-Z из трёх дисков по 500 МБ? Почему не 1.5 ГБ и не 1.0 ГБ?

Пояснение: В RAID-Z из трёх дисков один диск уходит под чётность. Полезный объём примерно равен сумме двух дисков (около 960 МБ).

Этап 2: Dataset'ы и их свойства

2.1 Создание dataset'ов

Dataset — это файловая система внутри пула. Она ведёт себя как отдельный раздел, но использует общее пространство пула.

Создаём несколько dataset'ов внутри rzpool

zfs create rzpool/documents
zfs create rzpool/music
zfs create rzpool/backup

Проверяем

zfs list

Вопрос: Где физически находятся эти три dataset'а? Они занимают отдельное место на дисках?

Пояснение: Dataset'ы — это не отдельные разделы, а просто разные "папки" с общим пулом пространства. Они делят всё свободное место в пуле.

2.2 Включение сжатия

Включаем сжатие lz4 для dataset'а documents

zfs set compression=lz4 rzpool/documents
zfs get compression rzpool/documents

Создаём файл с повторяющимся содержимым (хорошо сжимается)

dd if=/dev/zero of=/rzpool/documents/zeros.dat bs=1M count=50

Смотрим, сколько места реально заняло

ls -lh /rzpool/documents/zeros.dat
zfs list rzpool/documents

Вопрос: Почему файл размером 50 МБ занимает на диске всего несколько мегабайт? Где "спрятались" остальные байты?

Пояснение: Сжатие lz4 работает в реальном времени. Данные сжимаются перед записью на диск. Файл, заполненный нулями, сжимается почти до нуля.

2.3 Настройка квоты

Устанавливаем квоту 100 МБ на dataset backup

zfs set quota=100M rzpool/backup
zfs get quota rzpool/backup

Пытаемся записать больше квоты

dd if=/dev/urandom of=/rzpool/backup/bigfile bs=1M count=150

Вопрос: Что произошло? Почему запись прервалась?

Пояснение: Квота ограничивает максимальный размер dataset'а. При попытке превысить квоту операция записи завершается ошибкой "Disk quota exceeded".

Пытаемся записать больше квоты по другому

rm /rzpool/backup/bigfile
dd if=/dev/zero of=/rzpool/backup/bigfile bs=1M count=150

Вопрос: Что произошло сейчас? Почему запись не прервалась по квоте?

Пояснение: Квота в ZFS ограничивает логический размер данных после сжатия и дедупликации, а dd пишет физические нули, которые ZFS сжимает почти в ничто.

Этап 3: Снапшоты и откат

3.1 Создание снапшота

Снапшот — это "мгновенный снимок" состояния файловой системы.

Создаём тестовые файлы в dataset documents

echo "Важный документ" > /rzpool/documents/important.txt
echo "Секретные данные" > /rzpool/documents/secret.txt

Создаём снапшот

zfs snapshot rzpool/documents@before_changes
zfs list -t snapshot

Вопрос: Сколько места занял снапшот? (Подсказка: посмотрите в zfs list поле USED для снапшота)

Пояснение: Снапшот в момент создания не занимает места. Он просто "запоминает", какие блоки данных принадлежат текущему состоянию. Место начнёт заниматься, когда данные будут меняться.

3.2 Изменение данных и наблюдение за ростом снапшота

Модифицируем существующий файл

echo "Дополнительная строка" >> /rzpool/documents/important.txt

Создаём новый файл

echo "Новый файл" > /rzpool/documents/newfile.txt

Удаляем один файл

rm /rzpool/documents/secret.txt

Смотрим, как изменился снапшот

zfs list -t snapshot
zfs list rzpool/documents

Вопрос: Почему снапшот теперь занимает место? Какие блоки "заморожены" в снапшоте?

Пояснение: При изменении или удалении файлов ZFS не трогает старые блоки — они сохраняются для снапшота. Снапшот начинает занимать ровно столько места, сколько занимали изменённые или удалённые данные.

3.3 Откат к снапшоту

Посмотрим текущее содержимое

ls -la /rzpool/documents/

Откатываемся к состоянию снапшота

zfs rollback rzpool/documents@before_changes

Проверяем, что вернулось

ls -la /rzpool/documents/
cat /rzpool/documents/important.txt

Вопрос: Что произошло с файлами newfile.txt и secret.txt? Почему important.txt вернул исходное содержимое?

Пояснение: zfs rollback возвращает файловую систему в точности к состоянию на момент создания снапшота. Все изменения, сделанные после снапшота, безвозвратно теряются.

Этап 4: Иллюзия свободного места — почему df врёт

4.1 Создание ситуации, когда df показывает не то, что есть

Создаём новый dataset без квоты

zfs create rzpool/test

Записываем в него данные

dd if=/dev/urandom of=/rzpool/test/data1.dat bs=1M count=200
dd if=/dev/urandom of=/rzpool/test/data2.dat bs=1M count=200

Смотрим, что показывает df

df -h /rzpool/test
zfs list rzpool/test
Вопрос: Цифры совпадают? Если нет, то почему?

4.2 Создание снапшотов, которые "съедают" место незаметно

Создаём серию снапшотов

zfs snapshot rzpool/test@snap1
dd if=/dev/urandom of=/rzpool/test/data3.dat bs=1M count=100

zfs snapshot rzpool/test@snap2
rm /rzpool/test/data1.dat

zfs snapshot rzpool/test@snap3
dd if=/dev/urandom of=/rzpool/test/data4.dat bs=1M count=150

Теперь смотрим

df -h /rzpool/test
zfs list -t all rzpool/test

Вопрос: Почему df показывает, что свободно 150 МБ, а zfs list говорит, что занято уже почти всё? Куда делось место?

Пояснение: df показывает свободное место в текущем состоянии dataset'а. Но снапшоты держат старые версии файлов! В сумме данные + снапшоты занимают гораздо больше места, чем видит df. Это классическая "ловушка" ZFS — место может закончиться внезапно, если забыть про снапшоты.

4.3 Удаление снапшотов и освобождение места

Удаляем снапшоты по одному и наблюдаем

zfs destroy rzpool/test@snap1
zpool list rzpool

zfs destroy rzpool/test@snap2
zpool list rzpool

zfs destroy rzpool/test@snap3
zpool list rzpool

Финальная проверка

zfs list rzpool/test
df -h /rzpool/test
Пояснение: Только после удаления всех снапшотов, ссылающихся на старые блоки, место действительно освобождается. zpool list показывает реальную картину использования пула.

Этап 5: Демонстрация невозможности расширить RAID-Z добавлением диска

5.1 Создание RAID-Z и попытка расширения

Создаём RAID-Z из трёх дисков

zpool destroy rzpool
zpool create rzexp raidz /dev/loop1 /dev/loop2 /dev/loop3
zpool list rzexp
zfs list rzexp<

5.2 Попытка добавить диск

Пытаемся добавить четвёртый диск в пул

zpool add rzexp /dev/loop4

Диск не добавился, но ZFS сообщила, что его можно добавить принудительно.

zpool add -f rzexp /dev/loop4

Диск добавился! Но увеличился ли полезный объём?

zpool list rzexp

Полезный объём кажется увеличился, но все ли у нас хорошо?

zpool status rzexp

Вопрос: Что показывает zpool status? Какой тип у нового vdev?

Пояснение: Добавленный диск /dev/loop4 стал отдельным vdev типа single (одиночный диск без избыточности). Он не объединился с существующим RAID-Z. В ZFS нельзя просто так расширить RAID-Z добавлением диска — можно только добавить ещё один RAID-Z vdev (что потребует 3 новых диска) или заменить все существующие диски на более ёмкие.

Попробуем отключить добавленный диск

zpool remove rzexp /dev/loop4

«Все, приплыли!» vdev удалить нельзя.
Вывод: флагом -f стоит пользоваться с огромной осторожностью.

5.3 Правильный способ: замена дисков на более ёмкие

Удалим «испорченый пул» и приготовим loop-устройства большего объема

zpool destroy  rzexp
losetup -d /dev/loop5
losetup -d /dev/loop4
for i in {4..6}; do dd if=/dev/zero of=disk$i.img bs=1M count=800; done

Проверяем что вышло

lsblk | grep loop

Пересоздадим pool rzexp

zpool create rzexp raidz /dev/loop1 /dev/loop2 /dev/loop3

Проверяем что получилось

zpool list rzexp

Заменяем дисками большего размера

zpool replace rzexp /dev/loop1 /dev/loop4
zpool replace rzexp /dev/loop2 /dev/loop5
zpool replace rzexp /dev/loop3 /dev/loop6

zpool online -e rzexp /dev/loop4
zpool online -e rzexp /dev/loop5
zpool online -e rzexp /dev/loop6

Проверяем что получилось

zpool list rzexp
Пояснение: Единственный способ увеличить ёмкость RAID-Z — заменить все диски по одному на диски большего размера. После замены каждого диска пул перестраивается (resilver), и после замены всех дисков объём автоматически увеличивается.

Этап 6: Очистка

Отключаем пулы 

zpool destroy rzexp

Отключаем loop-устройства

losetup -D

Удаляем файлы-образы

rm -f disk*.img

Проверяем, что всё чисто

zpool list
lsblk | grep loop

Контрольные вопросы

  1. В чём разница между пулом (zpool) и dataset'ом (zfs)?
  2. Почему при создании снапшота он не занимает места, а потом начинает занимать?
  3. Какая команда показывает реальное занятое место в пуле, а не в отдельном dataset?
  4. Почему df может показывать 50% свободного места, а запись данных внезапно прекращается?
  5. Можно ли добавить один диск в RAID-Z и увеличить его ёмкость? Почему?
  6. Как работает сжатие в ZFS и почему файл из нулей занимает почти ноль места?
  7. Что произойдёт с данными, если выполнить zfs rollback к старому снапшоту?

Выводы

  • ZFS объединяет управление томами и файловой системой в одном инструменте.
  • Пул — это набор дисков. Dataset — файловая система внутри пула.
  • Снапшоты в ZFS мгновенны и сначала не занимают места.
  • df может вводить в заблуждение — используйте zfs list и zpool list.
  • RAID-Z нельзя расширить добавлением одного диска — только заменой всех дисков на более ёмкие или добавлением нового RAID-Z vdev.
  • Сжатие работает в реальном времени и особенно эффективно для текста и нулей.
