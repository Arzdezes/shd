Лабораторная работа: iSCSI Multipath (MPIO) с scsitarget-utils

Тема: Настройка многопутевого доступа (MPIO) к iSCSI Target на базе scsitarget-utils, отказоустойчивость и балансировка нагрузки между двумя сетевыми путями.

Цель работы: Научиться настраивать iSCSI Target с двумя сетевыми порталами (используя несколько initiator-address или несколько конфигураций), подключать клиент через два сетевых интерфейса, настраивать multipath для объединения путей в одно устройство, тестировать отказ одного сетевого пути.

Топология:

  • Сервер (Target): ALT Server 11 (виртуальная машина) — с двумя сетевыми интерфейсами:
    • eth0: 192.168.122.206
    • eth1: 192.168.123.206 (вторая подсеть)
  • Клиент (Initiator): ALT Workstation 10.4 (хостовая система) — с VirtualBox Host-Only интерфейсами:
    • vboxnet0: 192.168.122.1
    • vboxnet1: 192.168.123.1

Подготовка

1.1 Настройка двух сетевых интерфейсов на сервере (ВМ)

Эта конфигурация настраивается на уровне VirtualBox. Добавьте второй сетевой адаптер в настройках виртуальной машины:

На ВМ (ALT Server) проверяем интерфейсы

ip a

Должны увидеть eth0 и eth1

Если второй интерфейс не настроен, создайте конфигурацию в ALT Linux:

Создаём конфигурацию для eth1

cat > /etc/net/ifaces/eth1/options << EOF
TYPE=eth
BOOTPROTO=static
SYSTEMCTL=yes
EOF

Указываем IP-адрес

cat > /etc/net/ifaces/eth1/ipv4address << EOF
192.168.123.206/24
EOF

Перезапускаем сеть

systemctl restart network

1.2 Настройка сетевых интерфейсов на клиенте (хост ALT Workstation)

VirtualBox создаёт интерфейсы vboxnet0 и vboxnet1 для Host-Only сетей. Назначим им IP-адреса:

Назначаем IP для первой сети

ip addr add 192.168.122.1/24 dev vboxnet0
ip link set vboxnet0 up

Назначаем IP для второй сети

ip addr add 192.168.123.1/24 dev vboxnet1
ip link set vboxnet1 up

1.3 Проверка доступности

Проверяем доступность сервера по обоим интерфейсам

ping -c 3 192.168.122.206
ping -c 3 192.168.123.206

1.4 Установка пакетов

На сервере:

apt-get install scsitarget-utils

На клиенте:

apt-get install open-iscsi multipath-tools

Этап 2: Настройка iSCSI Target с двумя порталами

Особенность scsitarget-utils: В отличие от targetcli, tgtd автоматически слушает на всех доступных IP-интерфейсах. Нет необходимости вручную создавать порталы — достаточно просто запустить сервис. Однако для наглядности и контроля доступа мы можем настроить несколько initiator-address для ограничения доступа.

2.1 Конфигурация Target

На сервере отредактируем /etc/tgt/targets.conf:

nano /etc/tgt/targets.conf

Добавим следующую конфигурацию:

<target iqn.2025-04.com.example:multipath.disk1>
    # Базовое устройство хранения<
    backing-store /srv/iscsi/disk1.img
    
    # Опции производительности
    write-cache on
    
    # Разрешаем доступ с обоих IP клиента (опционально)
    initiator-address 192.168.122.1
    initiator-address 192.168.123.1
</target>
Пояснение: Директива initiator-address может быть указана несколько раз для разных IP-адресов или подсетей . Также можно указать подсеть: initiator-address 192.168.122.0/24. По умолчанию tgtd слушает на всех интерфейсах, поэтому клиент сможет подключиться через любой IP сервера.

2.2 Запуск и проверка

Создаём образ диска (если ещё не создан)

mkdir -p /srv/iscsi
dd if=/dev/zero of=/srv/iscsi/disk1.img bs=1M count=1024

Запускаем сервис

systemctl restart tgtd

Проверяем, что цель создана

tgt-admin --show

Этап 3: Обнаружение целей с двух интерфейсов

3.1 Настройка клиента

На клиенте:

Убеждаемся, что iscsid запущен

systemctl start iscsid

3.2 Обнаружение целей через разные IP

Обнаружение через первый интерфейс сервера

iscsiadm -m discovery -t sendtargets -p 192.168.122.206

Обнаружение через второй интерфейс сервера

iscsiadm -m discovery -t sendtargets -p 192.168.123.206

3.3 Проверка записей в базе данных

Просмотр всех обнаруженных целей

cat /etc/iscsi/nodes/iqn.2025-04.com.example:multipath.disk1/*/default
Пояснение: Теперь в базе данных open-iscsi есть две записи для одного и того же target, но с разными IP-адресами.

3.4 Подключение к цели

Подключаемся ко всем обнаруженным целям

iscsiadm -m node --login
Важно: После выполнения этой команды должно установиться два соединения (две сессии) с одним и тем же target через разные IP-адреса.

3.5 Проверка подключения

Просмотр сессий

iscsiadm -m session

Более детальная информация (видим два соединения)

iscsiadm -m session -P 1

Просмотр блочных устройств

lsblk

Вопрос: Сколько блочных устройств появилось? Почему их два, хотя у нас один LUN?

Пояснение: При подключении через два разных сетевых пути open-iscsi создаёт два независимых блочных устройства (например, /dev/sda и /dev/sdb), представляющих один и тот же удалённый диск. Multipath решает эту проблему, объединяя их в одно устройство.

Этап 4: Настройка Multipath

4.1 Конфигурация multipath

На клиенте:

Создаём конфигурационный файл

cat > /etc/multipath.conf << 'EOF'
defaults {
    user_friendly_names yes
    find_multipaths yes
}

blacklist {
    devnode "^(ram|raw|loop|fd|md|dm-|sr|scd|st)[0-9]*"
    devnode "^hd[a-z]"
}

devices {
    device {
        vendor "IET"
        product "VIRTUAL-DISK"
        path_grouping_policy multibus
        path_checker tur
        features "0"
        hardware_handler "0"
        prio const
        failback immediate
        rr_weight uniform
        no_path_retry 5
    }
}
EOF
Пояснение: В ALT Linux для работы multipath необходим этот файл конфигурации. Vendor "IET" — это идентификатор, который используется tgtd по умолчанию. Параметр find_multipaths yes облегчает обнаружение multipath устройств.

4.2 Запуск multipathd

Запускаем сервис

systemctl enable multipathd
systemctl start multipathd

Проверяем статус

systemctl status multipathd

4.3 Обнаружение и проверка multipath устройств

Принудительное обнаружение мультипафа

multipath -v2

Просмотр карты устройств

multipath -ll

Вы должны увидеть одно multipath устройство, объединяющее оба пути.

Пример вывода:

mpatha (360000000000000000e00000000010001) dm-0 IET     ,VIRTUAL-DISK
size=1.0G features='0' hwhandler='0' wp=rw
`-+- policy='round-robin 0' prio=1 status=active
  |- 3:0:0:1 sda 8:16 active ready running
  `- 4:0:0:1 sdb 8:32 active ready running
Пояснение: multipath создаёт устройство /dev/mapper/mpatha (или /dev/mapper/XXX), которое представляет оба пути. При политике round-robin оба пути используются для балансировки нагрузки.

4.4 Форматирование и монтирование multipath устройства

Форматируем устройство из /dev/mapper/

mkfs.ext4 /dev/mapper/mpatha

Создаём точку монтирования

mkdir -p /mnt/multipath

Монтируем

mount /dev/mapper/mpatha /mnt/multipath

Проверяем

df -h /mnt/multipath

4.5 Тестирование записи

Записываем тестовые данные

echo "Multipath test data with scsitarget-utils" > /mnt/multipath/test.txt
dd if=/dev/urandom of=/mnt/multipath/bigfile.dat bs=1M count=50

Проверяем

ls -la /mnt/multipath/

Этап 5: Тестирование отказоустойчивости

5.1 Мониторинг активных путей

На клиенте (в одном терминале):

Запускаем непрерывный мониторинг

watch -n 1 multipath -ll

На клиенте (в другом терминале):

Запускаем непрерывную запись для имитации нагрузки

while true; do date >> /mnt/multipath/log.txt; sleep 0.1; done

5.2 Симуляция отказа сетевого пути

Мы можем временно отключить один из интерфейсов на сервере или клиенте:

Вариант 1: На сервере (отключаем второй интерфейс)

На сервере

ip link set eth1 down

Вариант 2: На клиенте (отключаем второй интерфейс)

На клиенте

ip link set vboxnet1 down

5.3 Наблюдение за переключением

Следите за выводом multipath -ll в первом терминале. Один из путей должен перейти в состояние faulty или failed.

Вопрос: Остановилась ли операция записи? Что произошло с multipath устройством?

Пояснение: Multipath автоматически переключает трафик на работающий путь. Для приложения это происходит незаметно. Время переключения зависит от настроек таймаутов.

5.4 Восстановление отказавшего пути

На сервере или клиенте (возвращаем интерфейс):

Поднимаем интерфейс

ip link set eth1 up

Через несколько секунд путь должен восстановиться и стать активным снова.

5.5 Остановка тестовой записи

Используйте Ctrl+C в терминале с while циклом.

Проверяем, что данные не потеряны

tail /mnt/multipath/log.txt

Этап 6: Настройка CHAP для двух путей

Если требуется настроить аутентификацию при использовании multipath, CHAP нужно сконфигурировать для каждого пути отдельно.

6.1 Настройка на сервере

На сервере добавим CHAP в конфигурацию:

nano /etc/tgt/targets.conf

Добавим директиву incominguser:

<target iqn.2025-04.com.example:multipath.disk1>
    backing-store /srv/iscsi/disk1.img
    write-cache on
    initiator-address 192.168.122.1
    initiator-address 192.168.123.1
    incominguser multipath_user multipath_secret
</target>

Перезагружаем конфигурацию:

systemctl restart tgtd

6.2 Настройка на клиенте

На клиенте редактируем /etc/iscsi/iscsid.conf:

nano /etc/iscsi/iscsid.conf

Установите:

node.session.auth.authmethod = CHAP
node.session.auth.username = multipath_user
node.session.auth.password = multipath_secret

discovery.sendtargets.auth.authmethod = CHAP
discovery.sendtargets.auth.username = multipath_user
discovery.sendtargets.auth.password = multipath_secret

Затем переподключитесь:

iscsiadm -m node --logout
iscsiadm -m discovery -t sendtargets -p 192.168.122.206
iscsiadm -m discovery -t sendtargets -p 192.168.123.206
iscsiadm -m node --login

После этого multipath должен работать с аутентификацией.

Этап 7: Очистка

На клиенте:

Размонтируем

umount /mnt/multipath

Отключаем multipath устройство

multipath -f mpatha

Останавливаем multipathd

systemctl stop multipathd

Отключаем iSCSI сессии

iscsiadm -m node --logout

Удаляем цели из базы

iscsiadm -m node -p 192.168.122.206 -o delete
iscsiadm -m node -p 192.168.123.206 -o delete

Удаляем конфигурацию multipath

rm -f /etc/multipath.conf

На сервере:

Останавливаем сервис

systemctl stop tgtd

Удаляем образ диска

rm -f /srv/iscsi/disk1.img

Выводы

  • Для отказоустойчивости iSCSI необходимо настроить два независимых сетевых пути между Target и Initiator.
  • scsitarget-utils (демон tgtd) автоматически слушает на всех доступных IP-интерфейсах сервера, что упрощает настройку MPIO.
  • При подключении к одному LUN через два пути open-iscsi создаёт два блочных устройства.
  • Multipath (пакет multipath-tools) объединяет эти устройства в одно, обеспечивая отказоустойчивость и балансировку нагрузки.
  • В ALT Linux конфигурация multipath задаётся в /etc/multipath.conf.
  • CHAP-аутентификацию можно (и нужно) использовать вместе с multipath, добавляя директиву incominguser в /etc/tgt/targets.conf.
