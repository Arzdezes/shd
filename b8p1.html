Лабораторная работа №1: Развёртывание кластера Proxmox VE

Цель работы: Установить и настроить кластер Proxmox VE из трёх узлов, интегрировать распределённое хранилище Ceph RBD как общее хранилище для виртуальных машин.

Подготовка

1.1 Создание клонов и донастройка после клонирования

У нас есть базовая ВМ с установленной "Альт Виртуализация редакция PVE 11.0". Из этой ВМ создадим еще два клона.

На каждом клоне (PVE-02, PVE-03) после клонирования выполняем: 
su -
Шаг 1: Удаление и генерация нового machine-id 
rm -f /etc/machine-id; systemd-machine-id-setup

Пояснение: machine-id — это уникальный идентификатор системы, используемый systemd, D-Bus и некоторыми сетевыми сервисами. При клонировании ВМ все копии получают одинаковый ID, что может вызвать конфликты (особенно в кластере и при работе DHCP). Удаление и генерация нового ID решает эту проблему.

Шаг 2: Изменение имени хоста 
# Устанавливаем новое имя хоста
# Для PVE-02:
hostnamectl set-hostname pve-02

# Для PVE-03:
hostnamectl set-hostname pve-03

# Проверяем
hostnamectl

Пояснение: Имя хоста должно быть уникальным в пределах кластера. В противном случае Proxmox не сможет корректно сформировать кластер.

1.2 Настройка сети на каждом узле PVE

Особенность ALT Виртуализация 11: Для настройки сети используется файл /etc/network/interfaces (в стиле Debian), а не традиционная для ALT Linux система /etc/net/ifaces/.

На каждом узле (PVE-01, PVE-02, PVE-03) выполняем:

su -

Редактируем конфигурацию сети:

nano /etc/network/interfaces

Приводим файл к следующему виду (для каждого узла — свой IP):

Для PVE-01:

auto lo
iface lo inet loopback

iface enp1s0 inet manual

auto vmbr0
iface vmbr0 inet static
    address 192.168.56.101/24
    gateway 192.168.56.1
    bridge-ports enp1s0
    bridge-stp off
    bridge-fd 0
    dns-nameservers 192.168.56.1

Для PVE-02:

auto lo
iface lo inet loopback

iface enp1s0 inet manual

auto vmbr0
iface vmbr0 inet static
    address 192.168.56.102/24
    gateway 192.168.56.1
    bridge-ports enp1s0
    bridge-stp off
    bridge-fd 0
    dns-nameservers 192.168.56.1

Для PVE-03:

auto lo
iface lo inet loopback

iface enp1s0 inet manual

auto vmbr0
iface vmbr0 inet static
    address 192.168.56.103/24
    gateway 192.168.56.1
    bridge-ports enp1s0
    bridge-stp off
    bridge-fd 0
    dns-nameservers 192.168.56.1

И переинициализирем сеть

systemctl restart ifupdown2-pre.service

Пояснение: В ALT Виртуализация 11 используется стандартный для Proxmox способ настройки сети через /etc/network/interfaces. Это обеспечивает совместимость со скриптами PVE и SDN (Software-Defined Networking).

1.3 Настройка файла hosts

На каждом узле добавляем резолвинг всех трёх хостов:

cat >> /etc/hosts << EOF
192.168.56.101 pve-01 pve-01.local
192.168.56.102 pve-02 pve-02.local
192.168.56.103 pve-03 pve-03.local
EOF

Пояснение: Резолвинг по именам критически важен для работы кластера Proxmox и Ceph.

1.4 Проверка установки Proxmox VE

Убеждаемся, что Proxmox VE установлен и веб-интерфейс доступен:

systemctl status pveproxy
systemctl status pvedaemon

Ожидаемый результат: Оба сервиса активны (running).

# Проверяем версию PVE
pveversion -v

1.5 Подготовка дисков для Ceph

На каждом узле добавляем дополнительные диски для Ceph OSD:

# Просматриваем доступные диски
lsblk

# Для лабораторной работы используем дополнительные виртуальные диски
# Например, /dev/sdb и /dev/sdc

# Проверяем, что диски не смонтированы и не содержат данных
fdisk -l /dev/sdb

Пояснение: Для Ceph OSD нужны отдельные диски или разделы, не занятые системой.

Этап 1: Создание кластера Proxmox

1.1 Инициализация кластера на первом узле

На PVE-01:

# Создаём кластер с именем "lab-cluster"
pvecm create lab-cluster

# Проверяем статус
pvecm status

Ожидаемый результат: Узел PVE-01 является единственным членом кластера, quorum = 1.

1.2 Присоединение остальных узлов

На PVE-02 и PVE-03:

# Присоединяемся к кластеру
pvecm add 192.168.56.101

На PVE-01 (проверяем):

pvecm nodes

Ожидаемый результат: Все три узла отображаются в списке, quorum = 3.

Этап 2: Установка и настройка Ceph

2.1 Запускаем необходимые службы Ceph

На каждом узле:

systemctl enable --now \
    ceph-mon.target \
    ceph-mgr.target 
    ceph-osd.target \
    ceph-mds.target \
    ceph-radosgw.target

Пояснение: В ALT Виртуализации эти службы по умолчанию как правило выключены.

2.2 Инициализация Ceph-кластера

На PVE-01:

# Инициализация Ceph с указанием сети для публичного трафика
pveceph init --network 192.168.56.0/24

# Создание мониторов
pveceph mon create

# Создание менеджера
pveceph mgr create

Пояснение: Мониторы (MON) обеспечивают консенсус в кластере, менеджер (MGR) собирает метрики и предоставляет API.

На PVE-02 и PVE-03:

# Добавляем мониторы на каждом узле
pveceph mon create

2.3 Добавление OSD (Object Storage Daemons)

На каждом узле (для каждого дополнительного диска):

# Просматриваем доступные диски
lsblk

# Добавляем OSD на диске /dev/sdb
pveceph osd create /dev/sdb

# Если есть второй диск
pveceph osd create /dev/sdc

Пояснение: OSD — это демон, который хранит данные, обрабатывает репликацию, восстановление и перебалансировку. Для обеспечения отказоустойчивости требуется как минимум 3 OSD.

2.4 Создание пула Ceph

На PVE-01:

# Создаём пул для виртуальных машин
ceph osd pool create vm-storage 128

# Проверяем создание пула
ceph osd lspools

# Статус кластера Ceph
ceph -s

Пояснение: Пул — это логическая группа объектов в Ceph. Количество placement groups (PG) должно быть кратно числу OSD.

Этап 3: Интеграция Ceph RBD в PVE

3.1 Добавление RBD-хранилища в PVE

На PVE-01 (в веб-интерфейсе или CLI):

# Добавляем хранилище RBD
pvesm add rbd ceph-storage \
    --pool vm-storage \
    --content images,rootdir

Пояснение: RBD (RADOS Block Device) — это блочное устройство поверх Ceph, которое может использоваться как хранилище для виртуальных машин.

3.2 Проверка хранилища

# Просмотр всех хранилищ
pvesm status

# Детальная информация о хранилище
pvesm status --storage ceph-storage

Этап 4: Создание и миграция виртуальной машины

4.1 Создание виртуальной машины на RBD-хранилище

Через веб-интерфейс (https://192.168.56.101:8006):

  1. Войдите в веб-интерфейс PVE (логин: root, пароль: установленный при установке).
  2. Нажмите "Create VM" в правом верхнем углу.
  3. General: ID = 100, Name = "test-vm".
  4. OS: Выберите ISO-образ (можно загрузить через хранилище "local").
  5. System: Оставьте по умолчанию.
  6. Hard Disk: Bus/Device = SCSI, Storage = ceph-storage (RBD), Size = 10 GB.
  7. CPU: 1 socket, 2 cores.
  8. Memory: 2048 MB.
  9. Network: Bridge = vmbr0, Model = VirtIO.
  10. Завершите создание.

4.2 Установка гостевой ОС

Запустите ВМ и выполните установку базовой ОС (например, Альт Рабочая станция).

4.3 Живая миграция ВМ между узлами

Через веб-интерфейс:

  1. Выберите ВМ (ID 100) в дереве слева.
  2. Нажмите "Migrate" в верхней панели.
  3. Выберите целевой узел (например, pve-02).
  4. Установите флажок "Online" (живая миграция).
  5. Нажмите "Migrate".

Через CLI:

qm migrate 100 pve-02 --online

Вопрос: Сколько времени заняла миграция? Почему при использовании Ceph миграция практически мгновенна?

4.4 Проверка после миграции

# Проверяем, на каком узле теперь работает ВМ
qm status 100

# Проверяем местоположение диска (должен быть в Ceph, а не на локальном хранилище)
qm config 100 | grep scsi0

Пояснение: При использовании общего хранилища (Ceph RBD) при миграции передаётся только состояние RAM, а не диск. Это делает миграцию очень быстрой — менее 3 секунд для тестовой ВМ.

Этап 5: Мониторинг и диагностика

5.1 Мониторинг через веб-интерфейс

Откройте вкладку Ceph в левом меню PVE. Здесь доступны:

  • Status: Общее состояние кластера, версия, количество OSD.
  • Monitor: Статус мониторов.
  • Manager: Статус менеджеров.
  • OSD: Список OSD, их заполненность, состояние.
  • Pool: Информация о пулах (размер репликации, PG).
  • Configuration: Файлы конфигурации Ceph.

5.2 Мониторинг через CLI

# Общее состояние кластера
ceph -s

# Состояние OSD
ceph osd tree

# Состояние пулов
ceph osd pool ls detail

# Использование хранилища
ceph df

Вопрос: Что означает состояние HEALTH_WARN? Какие предупреждения могут возникать в только что созданном кластере?

Очистка

# Останавливаем тестовую ВМ
qm stop 100

# Удаляем ВМ
qm destroy 100
