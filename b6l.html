Лекция 8. Блочные сети: iSCSI

Цель лекции: Сформировать понимание принципов работы блочных сетей на примере iSCSI, объяснить отличие от файловых протоколов (NFS/SMB), архитектуру iSCSI (Target, Initiator, LUN, IQN), разобрать сценарии использования, производительность и безопасность.

Введение

На прошлых занятиях мы говорили о файловых сетевых протоколах — NFS и SMB. Они отлично подходят для организации общего доступа к файлам, где сервер управляет файловой системой, а клиент видит привычную структуру папок и файлов.

Но есть сценарии, где файловый доступ недостаточен:

  • Виртуализация: Гипервизору (VMware ESXi, KVM) нужно блочное устройство, на котором он сам создаст свою файловую систему и разместит виртуальные машины.
  • Базы данных: Некоторые СУБД работают эффективнее, когда имеют прямой доступ к блочному устройству.
  • Кластерные файловые системы: Требуют, чтобы все узлы видели один и тот же набор блоков (например, GFS2, OCFS2).
  • Загрузка с сети (iSCSI boot): Сервер может загружаться с удалённого диска, не имея локального накопителя.

Здесь на сцену выходят блочные сети. Самый распространённый протокол в этой категории — iSCSI (Internet Small Computer System Interface). Он позволяет передавать команды SCSI по TCP/IP-сети, превращая удалённое дисковое устройство в локальный диск.

Часть 1. От SCSI к iSCSI

1.1 Что такое SCSI?

SCSI (Small Computer System Interface) — это набор стандартов для подключения периферийных устройств (дисков, ленточных накопителей, сканеров), разработанный в 1980-х годах.

Ключевые понятия SCSI:

  • Initiator (инициатор): Устройство, которое инициирует операции (обычно компьютер).
  • Target (цель): Устройство, которое выполняет операции (диск, массив).
  • LUN (Logical Unit Number): Логический номер устройства внутри Target. Один Target может иметь несколько LUN (например, несколько виртуальных дисков).

SCSI был разработан как параллельный интерфейс (SCSI-1, SCSI-2, SCSI-3) — толстые кабели, ограниченная длина (до 12-25 метров), жёсткие требования к терминированию. Но сам протокол (набор команд) оказался настолько удачным, что его адаптировали для других физических интерфейсов.

1.2 Эволюция: SAS, Fibre Channel, iSCSI

Интерфейс Физическая среда Макс. длина Скорость Применение

1.3 Что такое iSCSI?

iSCSI — это протокол, который инкапсулирует SCSI-команды в TCP/IP-пакеты. Он позволяет:

  • Использовать существующую Ethernet-инфраструктуру для передачи SCSI-команд.
  • Организовывать блочный доступ к хранилищу на любом расстоянии (в пределах IP-сети).
  • Применять все преимущества TCP: надёжность, управление потоком, маршрутизация.

Аналогия: Если NFS и SMB — это доставка "заказных блюд" (файлов), то iSCSI — это доставка "ингредиентов" (сырых блоков), из которых клиент сам готовит своё блюдо.

Часть 2. Архитектура iSCSI

2.1 Компоненты

1. iSCSI Target (цель)

  • Это серверная часть, которая предоставляет блочные устройства по сети.
  • Target может быть:
    • Аппаратным (дисковый массив, SAN-контроллер).
    • Программным (Linux targetcli, Windows iSCSI Target, FreeBSD ctld).
  • Target идентифицируется по IQN (iSCSI Qualified Name).

2. iSCSI Initiator (инициатор)

  • Это клиентская часть, которая подключается к Target и получает блочное устройство.
  • Initiator может быть:
    • Встроенным в ОС (Linux: open-iscsi, Windows: Microsoft iSCSI Initiator).
    • Аппаратным (HBA — Host Bus Adapter, разгружающий CPU).
  • Initiator также имеет свой IQN.

3. LUN (Logical Unit Number)

  • Это виртуальный диск, который Target предоставляет Initiator'у.
  • LUN может быть создан на основе:
    • Физического диска.
    • RAID-массива.
    • Файла (file-backed LUN).
    • Тома LVM/ZFS.

4. IQN (iSCSI Qualified Name)

  • Уникальный идентификатор iSCSI-устройства.
  • Формат: iqn.yyyy-mm.naming-authority:unique-name
  • Пример: iqn.2025-03.com.example:storage.target1

5. Portal (портал)

  • Комбинация IP-адреса и TCP-порта (обычно 3260), на котором Target слушает соединения.

2.3 Этапы установки соединения

  1. Discovery (обнаружение): Initiator отправляет запрос на Target Portal, чтобы узнать доступные Target.
  2. Login (авторизация): Initiator аутентифицируется (CHAP) и устанавливает сессию.
  3. SCSI command flow: Initiator отправляет SCSI-команды (READ, WRITE, INQUIRY и т.д.), Target выполняет их и возвращает ответ.

Часть 3. Компоненты iSCSI в Linux

3.1 Software Initiator: open-iscsi

В Linux стандартным iSCSI-инициатором является пакет open-iscsi.

Основные файлы и команды:

  • /etc/iscsi/initiatorname.iscsi — содержит IQN инициатора.
  • /etc/iscsi/iscsid.conf — настройки (CHAP, таймауты).
  • iscsiadm — основная утилита управления.

Основные операции:

Просмотр IQN

cat /etc/iscsi/initiatorname.iscsi

Обнаружение Target

iscsiadm -m discovery -t st -p 192.168.1.10

Подключение к Target

iscsiadm -m node -T iqn.2025-03.com.example:storage.target1 -p 192.168.1.10 -l

Просмотр активных сессий

iscsiadm -m session

Отключение

iscsiadm -m node -T iqn.2025-03.com.example:storage.target1 -p 192.168.1.10 -u

После успешного подключения в системе появляется новое блочное устройство (например, /dev/sdb), с которым можно работать как с обычным диском — размечать, создавать ФС, монтировать.

3.2 Software Target: targetcli (LIO)

В Linux стандартным iSCSI-таргетом является LIO (Linux-IO Target), управляемый через утилиту targetcli.

Иерархия targetcli:

/
├── backstores/          # Хранилища (backstores)
│   ├── fileio/          # Файлы как LUN
│   ├── block/           # Блочные устройства как LUN
│   ├── pscsi/           # Физические SCSI-устройства
│   └── ramdisk/         # Оперативная память (для тестов)
├── iscsi/               # iSCSI targets
│   └── iqn.2025-03.com.example:storage.target1/
│       └── tpg1/        # Target Portal Group
│           ├── portals/ # IP:порт
│           ├── luns/    # LUNs (ссылки на backstores)
│           └── acls/    # Access Control Lists
└── loopback/            # Для локального подключения (без сети)

Пример настройки:

# Запуск targetcli
sudo targetcli

# Создание backstore из файла
/> backstores/fileio create file1 /srv/iscsi/disk1.img 10G

# Создание iSCSI target
/> iscsi/ create iqn.2025-03.com.example:storage.target1

# Создание портала (IP:порт)
/> iscsi/iqn.2025-03.com.example:storage.target1/tpg1/portals/ create 0.0.0.0 3260

# Создание LUN, указывающего на backstore
/> iscsi/iqn.2025-03.com.example:storage.target1/tpg1/luns/ create /backstores/fileio/file1

# Создание ACL (разрешить доступ конкретному инициатору)
/> iscsi/iqn.2025-03.com.example:storage.target1/tpg1/acls/ create iqn.1993-08.org.debian:01:client1

# Сохранение конфигурации
/> saveconfig
/> exit

3.3 Аутентификация: CHAP

CHAP (Challenge-Handshake Authentication Protocol) — это протокол аутентификации, используемый iSCSI.

На Target (в targetcli):

/> iscsi/iqn.2025-03.com.example:storage.target1/tpg1/acls/iqn.1993-08.org.debian:01:client1/
    set auth userid=clientuser
    set auth password=secretpass

На Initiator (в /etc/iscsi/iscsid.conf):

node.session.auth.authmethod = CHAP
node.session.auth.username = clientuser
node.session.auth.password = secretpass

3.4 Многопутевой доступ (MPIO, Multipath I/O)

Для отказоустойчивости и увеличения пропускной способности используют Multipath I/O. Initiator подключается к одному Target через несколько сетевых путей (разные сетевые интерфейсы, разные коммутаторы).

Схема:

Initiator ── eth0 ── Switch A ── Target (порт 1)
        └─── eth1 ── Switch B ── Target (порт 2)

В Linux за управление многопутевым доступом отвечает multipath-tools. Система видит одно устройство /dev/mapper/mpathX, которое объединяет несколько физических путей.

Часть 5. Сценарии использования iSCSI

5.1 Виртуализация (VMware ESXi, KVM)

Это самый популярный сценарий. Гипервизор подключается к iSCSI-таргету и видит LUN как локальный диск. На этом диске гипервизор создаёт свою файловую систему (VMFS для ESXi, LVM/QCOW2 для KVM) и размещает виртуальные машины.

Преимущества:

  • Централизованное управление хранилищем.
  • Живая миграция (vMotion, live migration) без перемещения данных.
  • Использование возможностей SAN (снапшоты, репликация).

5.2 Загрузка с сети (iSCSI Boot)

Серверы без локальных дисков (diskless) могут загружаться с iSCSI-диска. Для этого:

  1. В BIOS/UEFI настраивается сетевой загрузчик (iSCSI Boot Firmware Table).
  2. Сервер подключается к iSCSI-таргету, где находится загрузочный образ.
  3. Система загружается, корневая ФС находится на удалённом LUN.

Применение: Бездисковые рабочие станции, серверы в дата-центрах, упрощение замены оборудования.

5.3 Базы данных и высоконагруженные приложения

Некоторые СУБД (Oracle, MS SQL) работают эффективнее с прямым блочным доступом, особенно с использованием асинхронного ввода-вывода (AIO). iSCSI позволяет вынести дисковую подсистему на отдельное хранилище, сохранив производительность, близкую к локальным дискам.

5.4 Резервное копирование

iSCSI используется для предоставления "сырых" дисков бэкапным серверам. Это позволяет делать образные бэкапы (snapshot-based backups) и восстанавливать целые системы.

5.5 Кластерные файловые системы

Технологии типа GFS2, OCFS2, VMFS требуют, чтобы все узлы кластера имели одновременный доступ к одним и тем же блочным устройствам. iSCSI предоставляет такую возможность, позволяя строить кластеры на стандартном Ethernet.

Часть 6. Производительность, безопасность, отказоустойчивость

6.1 Производительность

Факторы, влияющие на производительность iSCSI:

  1. Сетевая инфраструктура:
    • Рекомендуется выделенная сеть (VLAN или физически отдельные коммутаторы).
    • Использование Jumbo Frames (MTU 9000) снижает оверхед.
    • Для высоких нагрузок — 10/25/40/100 GbE.
  2. TCP-параметры:
    • Настройка TCP-буферов (net.ipv4.tcp_rmem, tcp_wmem).
    • Включение TCP offloading на сетевых картах (TSO, LRO).
  3. Аппаратный iSCSI HBA:
    • Специализированные карты разгружают CPU от обработки TCP/IP и SCSI.
    • Обеспечивают загрузку с iSCSI (iSCSI Boot).
  4. iSCSI vs NFS:
    • Для баз данных iSCSI часто показывает лучшие результаты из-за меньшего оверхеда на уровне протокола.
    • Для файловых серверов NFS может быть проще и достаточно производительным.

6.2 Безопасность

Рекомендации:

  • Выделенная сеть: iSCSI не должен идти через публичные сети без шифрования.
  • CHAP: Обязательная аутентификация (как однонаправленный, так и двунаправленный CHAP).
  • ACL: Ограничение доступа по IQN и IP-адресам.
  • Шифрование: При использовании по открытым сетям — IPsec (iSCSI не имеет встроенного шифрования, в отличие от SMB 3.0 или NFSv4.2).
  • Сетевое разделение: Использование VLAN, изоляция трафика iSCSI от остального.

6.3 Отказоустойчивость

  1. Multipath I/O (MPIO):
    • Несколько сетевых путей между Initiator и Target.
    • Автоматическое переключение при отказе канала или коммутатора.
    • Балансировка нагрузки (round-robin).
  2. Кластеризация Target:
    • Active-Passive кластеры iSCSI-таргетов (например, на основе DRBD или корпоративных SAN).
    • При отказе одного Target, Initiator переподключается к другому (может потребоваться настройка таймаутов).
  3. Репликация:
    • На уровне хранилища (LUN-репликация).
    • Синхронная или асинхронная на удалённую площадку.
  4. Настройка таймаутов:
    • Важно правильно настроить таймауты iSCSI (например, node.session.timeo.replacement_timeout), чтобы система не "падала" при временных проблемах сети.

Часть 7. Ограничения и подводные камни

  1. TCP-зависимость: iSCSI использует TCP, что означает:
    • При потере пакетов происходит ретрансляция, что может привести к росту задержек.
    • Для критичных нагрузок требует качественной сети.
  2. Коррупция данных: Если несколько инициаторов одновременно пишут в один LUN без кластерной файловой системы, данные будут разрушены. iSCSI не предотвращает это — ответственность на администраторе.
  3. Производительность при синхронной записи: Если LUN размещён на файле (fileio), а не на блочном устройстве (block), может быть дополнительный оверхед.
  4. Сложность отладки: Проблемы iSCSI часто связаны с сетью, но проявляются как проблемы диска. Диагностика требует опыта.
  5. Совместимость: Разные реализации iSCSI (Microsoft iSCSI Target, LIO, FreeBSD ctld) могут иметь нюансы совместимости, особенно с продвинутыми функциями (VAAI, ODX).

Резюме и вопросы

Ключевые выводы:

  1. iSCSI — это протокол блочного доступа по IP-сетям, инкапсулирующий SCSI-команды в TCP/IP.
  2. Основные компоненты: Initiator (клиент) и Target (сервер), идентифицируемые по IQN.
  3. В Linux iSCSI реализуется через open-iscsi (Initiator) и targetcli/LIO (Target).
  4. iSCSI позволяет строить централизованные хранилища для виртуализации, загрузки с сети, баз данных.
  5. Для отказоустойчивости используется Multipath I/O (MPIO).
  6. По сравнению с NFS/SMB — это блочный доступ (низкоуровневый), по сравнению с Fibre Channel — более доступный, но с большей загрузкой CPU и задержками.
  7. Безопасность обеспечивается выделенными сетями, CHAP-аутентификацией и ACL.
